# Handoff — monitoring Optimus in live sessions (updated 2026-10-24)

Read this first in a session whose job is to watch Optimus run in other sessions, judge it from files rather than impressions, and fix what the live tests expose. This file is the carrier between machines: Claude Code's own memory directory is per machine, so everything a monitoring session needs is written here. Private details of the owner's projects are kept out on purpose; the owner's own notes hold them.

The plugin was called `project-memory` until 2026-10-20; the rename touched every identifier (`~/.optimus`, `OPTIMUS_HOME`, `OPTIMUS_BANK`, `OPTIMUS_DEVICE`, plugin id `optimus@optimus`, MCP server `optimus`).

## Setting up a second machine to monitor from

1. The bank's remote exists (see above). The new machine needs access to that private repository before it clones: an SSH key added to the owner's GitHub account (the remote is SSH), or `gh auth login` followed by `gh auth setup-git` with the HTTPS form `https://github.com/GageBachik/knowledge-bank.git`. `kb sync` calls plain `git`, so whatever credential makes a manual `git fetch` work makes sync work.
2. On the new machine: install Claude Code and Node 24.4 or later, then follow README → Install (from GitHub) or README → Develop (in place from a clone, which is what a monitoring session wants, since it may change the plugin). Then `kb setup`, `kb init --clone git@github.com:GageBachik/knowledge-bank.git`, `kb doctor` (expect `bank-remote  origin reachable`), and restart Claude Code. After the first turn `kb doctor` should also show `last-sync  ok`; from then on both machines push to the same repository and each sees what the other recorded after its next sync.
3. Where things are on the new machine: state in the home directory's `.optimus` folder (on Windows `%USERPROFILE%\.optimus`); Claude Code's transcripts in the home directory's `.claude/projects/<slug>/<session>.jsonl`, where the slug is the working directory with its separators replaced by `-`; the plugin folder from `claude plugin list --json` (`readFromFolder` when installed in place, else `installPath`).
4. Hooks are registered as the `node` program with an argument list, no shell, so they run the same on Windows and Linux; `kb sync` is spawned with the running Node binary. The README gives the `kb` function for zsh, bash and PowerShell. Every command a brief tells a session to run quotes the plugin path and uses forward slashes, because Claude Code's Bash tool on Windows is Git Bash, which strips unquoted backslashes (audit of 2026-10-24). The state watcher below needs only the tools Git for Windows ships; the log watcher is node.
5. Then read "How to watch a session" below and re-arm the watchers.

## How to run a build

A knowledge build turns a project's imported memories and repo documents into approaches, targets and findings (the Mac's on 2026-10-17, the Windows PC's on 2026-10-24). Since 2026-10-24 the mechanical parts are `kb build`; the reading and judging are the session's agents. Per project, from a folder with its `.kb.json` (or anywhere with `--project <id>`), with `kb` spelled as `node "<plugin>/dist/kb.js"`:

1. `kb import all` first, so the memories are evidence notes in the index; `kb sync` so the other machine's imports are here too (the manifest lists memories from every device; a memory whose original is on the other machine is read from its `bank_file`).
2. `kb build manifest --out <scratch>/manifest.json` — one entry per shard of at most 36 memories (`--shard <n>`), the repo's documents on shard 1, each with the domain's vocabulary. Check the summary lines: a project with 0 notes and 0 docs has nothing to build.
3. One extractor agent per shard, in parallel: its prompt is `kb build brief` (extractor) plus its shard's JSON; it reads every memory and document in full and writes `<scratch>/<project>.<shard>.json`. Tell it to run `kb build validate <its file> [--keys <the earlier shards' files>]` before it reports, and to fix rather than drop what fails when the source supports the claim.
4. One reviewer agent per project, after its extractors: its prompt is `kb build brief --role reviewer` plus the shard files. It merges them in shard order into `<scratch>/<project>.json`, refutes what it cannot find in the cited source, deduplicates, and edits the repo's `.kb.json` (`facets`, `target`, `relies_on`). On 2026-10-24 one project's reviewer dropped 83 of 121 candidates and merged 18; that ratio is normal for ops-heavy memories.
5. `kb build validate <scratch>/<project>.json` must exit 0; `--fix` drops what still fails (one line per failure says why). Rehearse a large batch into a temporary bank first (`OPTIMUS_HOME` and `OPTIMUS_BANK` at empty folders, `kb init --bank`), then `kb write <scratch>/<project>.json` against the real one and `kb sync`.
6. Afterwards: `kb concepts review` (the tags create concepts and merge questions; open item 3), `kb map --open` to see the project's lane filled, and a note here of what was written.

## How to watch a session

Two background watchers, re-armed every 30 minutes (the Monitor tool caps a watch at 30 minutes):

```sh
# state watcher: new sessions, registrations, turn ends with context, compaction files, draft counts
S=~/.optimus; ME=<this session id>; touch $S/.watch-stamp; prev=$(wc -l < $S/metrics.jsonl | tr -d ' ')
while true; do
  m=$(wc -l < $S/metrics.jsonl | tr -d ' '); if [ "$m" != "$prev" ]; then last=$(tail -1 $S/metrics.jsonl); case "$last" in *"$ME"*) ;; *) echo "TURN ENDED: $(echo "$last" | cut -c1-120)";; esac; prev=$m; fi
  find $S/sessions -maxdepth 3 \( -name task-state.json -o -name audit.json \) -newer $S/.watch-stamp -not -path "*$ME*" | sed 's/^/COMPACTION STATE: /'
  find ~/projects ~ -maxdepth 2 -name .kb.json -newer $S/.watch-stamp | sed 's/^/KB.JSON WRITTEN: /'
  touch $S/.watch-stamp; sleep 2
done

# log watcher (a node filter: node is a plugin prerequisite on every machine, python is not; grep in a pipeline went deaf once on a machine that rewrites it)
tail -n0 -F ~/.optimus/logs/hooks.log | node -e 'const p=/"level":"(warn|error)"|auto-registered|domain settled|domain decision|pre-compact|post-compact|subagent drafts|asked the session to record|stop: turn judged|sync: /; require("readline").createInterface({input:process.stdin}).on("line",l=>{if(p.test(l))console.log(l.slice(0,260))})'
```

Judging a session afterwards, all from files: the transcript under `~/.claude/projects/<cwd-slug>/<session>.jsonl` holds the injected briefs (`attachment.type == hook_additional_context`), the prompts, tool calls and text; count the briefed finding ids (`[f_…]`) against the ids the assistant text cites; `metrics.jsonl` gives context per turn; `audit.json` gives present and missing per compaction; the bank findings for a project are `grep -l "^project: <id>" ~/knowledge-bank/notes/finding/*.md`; subagent transcripts that called `kb_write` are under `<session>/subagents/`. For v1.6: a `stop: asked the session to record` log line should be followed in the transcript by a user entry beginning `Stop hook feedback:` and a `kb_write` tool call; a second ask for the same statements is a defect. hooks.log has one `stop: turn judged` line per main-agent turn (`candidates`, `asked`, `wrote`, `continued`) and one `sync: <result>` line per sync, so a turn without a judged line means the Stop hook did not run.

An isolated end-to-end run of the Stop hook, when a change touches it: create a temporary folder with a `.kb.json` (`{"project_id":"e2e","domain":"tooling"}`), export `OPTIMUS_HOME` and `OPTIMUS_BANK` to temporary paths, `node <plugin>/dist/kb.js init --bank $OPTIMUS_BANK`, then `env -u CLAUDECODE claude -p --permission-mode bypassPermissions --output-format json "<a prompt that ends in one measured sentence>"` from that folder, and check the temporary `logs/hooks.log`, the temporary bank's `notes/finding/`, and the session transcript.

Rules that held up: measure before changing; one fix per observed failure with a test that pins it; commit only on a green suite; repair the bank by hand only to undo a plugin mistake; never commit inside the owner's other repositories; nothing unrelated is ever injected into a session.
